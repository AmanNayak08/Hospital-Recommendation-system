# Hospital Recommendation System

A notebook-based hospital comparison prototype that ranks hospitals
using a selected user location, straight-line distance, admission fees,
ratings, and general-ward bed availability. Results are displayed in an
interactive Folium map and a comparison table, with Google Maps driving
directions and hospital website links where available.

> **Project status:** Prototype. Bed availability comes from the
> supplied CSV dataset and is not verified live. This tool is for
> comparison/navigation support, not medical advice.

## Overview

The notebook loads hospital records from a CSV file, validates and
cleans the data, calculates the distance from a selected user location
to each hospital, and ranks hospitals using a weighted score. It labels
general-ward bed status as **Available**, **Limited**, or **Full** using
the bed counts and occupancy values present in the dataset.

The notebook also trains a Random Forest classifier on simulated user
locations. Its labels are generated by the project's rule-based ranking
logic. The current interactive interface displays the rule-based
ranking; classifier predictions are available separately through
`predict_ml()`.

## Problem Statement

Comparing hospitals may require considering distance, admission fee,
rating, and reported bed availability at the same time. This project
brings these attributes together in a ranked list and interactive map to
make comparison more convenient.

## Objectives

-   Load hospital records from a CSV file.
-   Validate required columns and clean selected invalid or missing
    data.
-   Calculate straight-line distance from the user's location to each
    hospital.
-   Rank hospitals using admission fee, distance, and rating.
-   Classify general-ward bed status.
-   Display results in a table and interactive map.
-   Provide directions and website links where available.
-   Demonstrate a Random Forest ML workflow using synthetic examples.

## Features

-   CSV loading and preprocessing with Pandas.
-   Coordinate validation and duplicate hospital-ID removal.
-   Location selection by manual coordinates, address geocoding, or
    approximate IP-based location.
-   Haversine straight-line distance calculation.
-   Weighted hospital score and configurable Top-N recommendations.
-   Available/Limited/Full bed-status labels.
-   Interactive Folium map and hospital comparison table.
-   Google Maps driving directions and optional hospital website links.
-   Save/load support through Joblib.

## Workflow

1.  **Load data:** read the hospital CSV into a Pandas DataFrame.
2.  **Clean data:** validate columns, convert numeric values, remove
    invalid coordinates and duplicate hospital IDs, and handle selected
    missing values.
3.  **Select location:** enter latitude/longitude, provide an address,
    or try approximate IP-based location.
4.  **Calculate distance:** estimate straight-line distance to each
    hospital with the Haversine formula.
5.  **Score and rank:** calculate the weighted score and apply
    bed-status sorting rules.
6.  **Show results:** display the ranked table and Folium map with
    markers, details, and directions.
7.  **Train and save ML model:** create synthetic examples,
    train/evaluate a Random Forest, and save the model bundle.

## Recommendation Logic

The notebook uses this score:

``` text
Score = -(fee_weight × admission_fee_inr)
        -(distance_weight × distance_km)
        +(rating_weight × rating_5)
```

Default weights:

  Setting                Default
  ------------------- ----------
  `FEE_WEIGHT`             `1.0`
  `DISTANCE_WEIGHT`        `1.0`
  `RATING_WEIGHT`       `1000.0`

With the defaults, the formula is `-fee - distance + 1000 × rating`.
Higher scores are preferred within the configured sorting rules. The
rating multiplier is much larger than the fee and distance multipliers,
so rating can dominate the score. This is a custom ranking value, not a
probability or clinical quality measure.

### Bed status rules

-   **Full:** available general-ward beds are zero or fewer.
-   **Limited:** not Full, but occupancy is at least 90% or five or
    fewer beds remain.
-   **Available:** neither condition above applies.

When `RANK_FULL_HOSPITALS_LAST = True`, hospitals with beds are sorted
before hospitals with no free beds. Score is then used, with distance as
a tie-breaker.

## Machine Learning

The notebook uses `RandomForestClassifier` from scikit-learn. It
generates simulated user locations and requested Top-N values, runs the
rule-based ranker, and uses the `recommended` flag as the binary label
(`1` = Recommended, `0` = Other). It uses a group-based train/test split
so records from the same simulated user stay together, reports metrics,
and fits a final classifier on all generated examples.

**Important:** the labels are synthetic and generated by the existing
ranking rules. Model accuracy indicates how well the classifier
reproduces those generated labels; it does not demonstrate real-world
medical usefulness. The current interface calls `model.rank()`, so the
displayed recommendations are rule-based. `model.predict_ml()` exposes
the classifier's predictions separately.

## Dataset Requirements

The CSV must contain these columns:

``` text
hospital_id
hospital_name
hospital_type
address
latitude
longitude
general_ward_total_beds
general_ward_available_beds
general_ward_occupancy_pct
admission_fee_inr
rating_5
review_count
```

A website field is optional. The notebook recognizes aliases such as
`website`, `website_url`, `hospital_website`, `url`, `link`, or `web`.

Data considerations: - Latitude must be between -90 and 90; longitude
between -180 and 180. - Duplicate `hospital_id` records are removed. -
Invalid numeric values may become missing values during conversion. -
Missing bed counts are currently filled with zero. This can confuse
unknown availability with confirmed zero beds; production systems should
distinguish these states. - Bed information should be timestamped and
checked against a trustworthy source.

## Run in Kaggle

The notebook's configured path is:

``` python
DATA_PATH = "/kaggle/input/datasets/abinashnayak11/hospital"
```

1.  Import `hospital-an-clean.ipynb` into Kaggle.
2.  Attach the hospital dataset using **Add Input**.
3.  Confirm the dataset path in the Input panel.
4.  Update `DATA_PATH` if necessary.
5.  Enable Internet in notebook settings if using address geocoding or
    IP-based location.
6.  Run notebook cells in order, including the final execution cell.

If the configured path is not a file, the notebook searches
`/kaggle/input/**/*.csv` for a CSV containing all required columns. If
no match is found, attach the correct dataset or update `DATA_PATH`.

## Run Locally

1.  Clone/download the repository and install dependencies.

2.  Place the hospital CSV in a local folder.

3.  Update `DATA_PATH`, for example:

    ``` python
    DATA_PATH = "./data/hospitals.csv"
    ```

4.  Start Jupyter:

    ``` bash
    jupyter notebook
    ```

5.  Open `hospital-an-clean.ipynb` and run all cells from top to bottom.

The automatic fallback search targets Kaggle's `/kaggle/input`
directory. For local use, set `DATA_PATH` to the actual local CSV path.

## Limitations

-   Bed availability is not fetched live; it is only as current as the
    CSV.
-   Haversine distance is straight-line distance, not road distance or
    travel time.
-   IP-based location may identify a server/network exit point rather
    than the user's device.
-   Missing bed counts are filled with zero by the current preprocessing
    logic.
-   ML labels are generated from rules rather than real patient
    outcomes.
-   The interface is designed for Jupyter/Kaggle and is not a deployed
    public website.
-   The score's rating weight is much larger than the other weights and
    can dominate ranking.

## Responsible Use

This is a hospital comparison and navigation prototype. It does not
diagnose medical conditions, determine urgency, or guarantee bed
availability at arrival. Users should contact hospitals to confirm
availability. In emergencies, contact local emergency services rather
than relying on this ranking alone.
